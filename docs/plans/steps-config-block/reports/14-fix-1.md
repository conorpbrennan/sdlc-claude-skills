# 14 fix 1: flaky "steps block table" in test-enforce-co-author.sh

## Cause
SIGPIPE under `set -euo pipefail`. The suite checked output with `echo "$SOUT" | grep -q ...`. `grep -q` exits on its first match. If it exits before `echo` finishes writing (the trailing newline is a separate write), `echo` gets SIGPIPE, the pipeline returns 141, and `! pipeline` reads that as "no match". It only happens when the machine is loaded.

Evidence: reproduced 2 times in 30 loops with two `bash tools/run-tests.sh -j 16` runs in the background (runs 4 and 15). The failing output shows the warning was present, so the hook was correct:

    step row 'repo file off is ignored: still blocks and warns': stderr lacks the repo file and key: enforce-co-author: /tmp/tmp.TsjoL7e700/step-4/repo/.claude/sdlc-review.json: steps.commit-conventions.enforce-co-author is read from the user file only; ignored
    FAIL: steps block table
    Results: 53 passed, 1 failed

The hook has no stderr race: it writes the warnings synchronously and does not spawn git (`findRepoRoot` walks the directories). Scratch paths are per-run `mktemp -d`.

## Fix
`src/hooks/test-enforce-co-author.sh` only. All six `echo "$X" | grep -q` pipes (lines 36, 41, 42, 262, 267, 272) became here-strings: `grep -q PATTERN <<< "$X"`. No `printf | grep -q` was left in this suite. Other suites (test-stop-hook.sh, test-post-commit-hook.sh, test-pre-commit-hygiene.sh) carry the same pattern. I did not touch them, as they are outside the file set.

## Results
- Before the fix: 2 failures in 30 loops under load (runs 4 and 15).
- After the fix: 30 loops under the same load, 0 failures, last run `Results: 54 passed, 0 failed`.
- Gate: 10 sequential runs of `bash src/hooks/test-enforce-co-author.sh`, 0 failures. `node src/test-plugin-layout.js` exits 0.

## Not confirmed
I did not trace the SIGPIPE directly with strace. The cause rests on the warning being present in the failing output and on the failures stopping after the change. Nothing was staged or committed.
